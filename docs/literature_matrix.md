| Source | Author / organisation | Version or date | URL | Access date | Key points | How it relates to this project | Limits |

| Incident Response Recommendations and Considerations for Cybersecurity Risk Management: A CSF 2.0 Community Profile (NIST SP 800-61 Rev. 3) | Alexander Nelson, Sanjay Rekhi, Murugiah Souppaya, Karen Scarfone (NIST) | April 2025, DOI 10.6028/NIST.SP.800-61r3. Replaces Rev. 2 (August 2012), the version linked in the project brief, which NIST withdrew on 3 April 2025 | https://csrc.nist.gov/pubs/sp/800/61/r3/final | 28 Nov 2026 | In the Detect function, element DE.AE (Adverse Event Analysis, PDF page 33) says the volume of potentially adverse events is generally quite high, so organisations should rely on technical solutions that filter large event datasets down to a subset suitable for human viewing and analysis. DE.AE-02 recommends tools that continuously monitor log events for known malicious and suspicious activity and generate reports on their findings. It also notes that anomalies may have benign or malicious foundations | Supports the purpose of this project for Chapter 1: filtering many log lines down to a small set of alerts that an analyst reviews. The note that anomalies can be benign is why alerts are described as worth checking and not as proof of an attack | General guidance. It does not define log formats, detection rules or thresholds, so those decisions are made and justified in this project |
| datetime: Basic date and time types, Python 3 documentation | Python Software Foundation | Python 3 documentation (version shown on the page when accessed: [3.15.2]) | https://docs.python.org/3/library/datetime.html | 28 Nov 2026 | `datetime.strptime(date_string, format)` returns a datetime and raises `ValueError` if the string does not match the format. Subtracting two datetime objects gives a `timedelta`, and `total_seconds()` gives the full duration. A naive object has no time zone information, and mixing naive and aware objects when subtracting raises `TypeError` | The parser uses `strptime` for the two accepted timestamp formats and rejects a line when `ValueError` is raised. The rules use `(last - first).total_seconds()` to check the time windows. All timestamps are naive, which matches the documented limitation that no time zone is stored | Time zones, daylight saving time and aware datetimes are not handled. The documentation does not say how to validate other parts of a log line |
| csv: CSV File Reading and Writing, Python 3 documentation | Python Software Foundation | Python 3 documentation (version shown on the page when accessed: [3.15.2]) | https://docs.python.org/3/library/csv.html | 28 Nov 2026 | `csv.reader` returns each row as a list of strings and converts no data types. With `DictReader`, a row with too few fields gets `None` for the missing values, and extra fields are stored as a list under the `restkey` key. Files should be opened with `newline=''` | The parser reads `sample_logs.csv` with this module and checks the number of fields in every row, so a row with 4 columns or an empty row is rejected with its line number. Timestamps and IPs stay strings until the parser validates and converts them | It only handles the structure of the file. It does not check whether a timestamp, IP address or username is valid |
| Date And Time Functions, SQLite documentation | SQLite (sqlite.org) | Page last updated 2026-07-11 (shown on the page) | https://sqlite.org/lang_datefunc.html | 28 Nov 2026 | SQLite has no dedicated date and time datatype. Dates and times can be stored as ISO-8601 text strings (for example `2025-05-29 14:16:00`), as Julian day numbers, or as Unix timestamps. `YYYY-MM-DD HH:MM:SS` is one of the supported text formats | Timestamps are stored as text in `YYYY-MM-DD HH:MM:SS`, the same format used in the data dictionary and in alert evidence, so the stored value is the same as the printed value | SQLite does not check that a stored string is a valid date, so validation must happen in the parser before saving |
